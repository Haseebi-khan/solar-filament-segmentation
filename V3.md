# v3 runbook

v3 implements the "FilaPQ v2" blueprint (rev 2.1) on top of v1 (nested OOF PQ 0.4381) and v2 (0.4438).
Every command runs from the repository root. Each stage is resumable and nothing is submitted to Kaggle.
Compliance and design decisions are in [DECISIONS.md](DECISIONS.md).

## Budget run (credit-limited, recommended)

The instance bills per hour, so `scripts/run_budget_v3.sh` runs a cheaper plan with a hard stop. Measured 20-step
benchmarks (60 epochs, per fold): M3 ResNet-34 @1536 0.28 h, M4 DINOv3 ViT-B @1536 1.33 h (80 GB), M5 DINOv3
ConvNeXt-S @1536 0.98 h (82 GB). M4/M5 use a light detail stem at 1536 px (`stem_native: false`, `stem_ch: [16, 32]`)
instead of the 2048 px stem, whose decoder alone costs about 2x a ResNet-34. The ViT-L / ConvNeXt-L members (M1/M2)
stay in the repo for a larger budget.

```bash
scripts/run_budget_v3.sh plan     # cost table for your credit
scripts/run_budget_v3.sh train    # M3 + M4 + M5, mini ablation, Stage C on everything; hard stop at credit - reserve
scripts/run_budget_v3.sh stop     # stop it now
scripts/run_budget_v3.sh stagec   # optional first: Stage C on the existing v2 maps only (no GPU, ~$1-2)
```

`train` overlaps the CPU stages (blend search, v2 selector, Stage C) with GPU training, because idle GPU time is
billed; after every finished member a submission from the members so far is written, so an early stop still leaves
a candidate. The final line of `logs/run_all_v3.out` names the recommended file and the 1 px variants
(`_erode1`, `_dilate1`) for the mask-width probe.

## One command

```bash
nohup scripts/run_all_v3.sh > logs/run_all_v3.out 2>&1 &
tail -f logs/run_all_v3.out              # stop everything: kill <pid on the first line>
```

It runs the steps below in order, skips finished work when restarted, and ends with a table of every candidate's
nested out-of-fold PQ plus the recommended file. `STOP_AFTER=prep|ablate|teachers` stops at a phase boundary.
`SKIP_ABLATIONS=1`, `SKIP_GONG=1` and `SKIP_STUDENTS=1` drop phases. The loss flags come from the ablations
(`src/choose_losses_v3.py`). The fallback settings of M1/M2 come from the 50-step benchmark against
`MAX_HOURS_M1/M2/M3` per fold. Blend weights come from `src/blend_search_v3.py`.

## Order of work (manual)

`scripts/run_v3.sh <stage>` wraps every step. Steps 1-3 run on the CPU and can start at once, also while the GPU trains.

| # | command | where / time | output, decision |
|---|---|---|---|
| 0 | `scripts/run_v3.sh tests` | CPU, ~1 min | all `ok` |
| 1 | `scripts/run_v3.sh diag` | CPU, ~15 min | `logs/final_v3_diag.txt`, `work/diag_v3/`: PQ lost by cause, ceilings. **M4 is promoted if fragmented + merged > 40 %.** |
| 2 | `nohup scripts/run_v3.sh stagec > logs/stagec_v3.out 2>&1 &` | CPU, ~1-2 h | Stage C on the v2 maps: linker, pool oracle, nested scorer, `submissions/submission_v3_r34_2048+effv2s_1536_w1-1_linker.csv`, bootstrap vs v2. **Lever B/C pays off if the gate says ADOPT.** |
| 3 | `nohup scripts/run_v3.sh gong > logs/gong_v3.out 2>&1 &` | network, ~2-4 h | domain check (`work/unlabeled/domain_check.md`), ~5k accepted frames (`U_images.npy`). Add the printed line to DECISIONS.md. |
| 4 | `scripts/run_v3.sh targets` | CPU, ~10 min | `work/cache/train_{skel,core}_*.npy`, `train_inst_1024.npy` |
| 5 | `scripts/run_v3.sh bench` | GPU, ~10-30 min | s/step, peak memory, projected hours per fold (`logs/final_v3_bench.txt`). Adjust `configs/m1/m2` (fallbacks are in the YAML comments). |
| 6 | `nohup scripts/run_v3.sh ablate > logs/ablate_v3.out 2>&1 &` | GPU, ~5-6 h | `logs/final_v3_ablations.txt`. Carry the winners into `configs/m*_v3.yaml` (`region`, `w_blob`, `w_sr`, heads). |
| 7 | `nohup scripts/run_v3.sh train m3_r34_1536_v3 m1_cnxl_2048_v3 m2_vitl_1536_v3 > logs/train_v3.out 2>&1 &` | GPU, ~25-40 h | `work/models/<member>/fold*.pt` |
| 8 | `scripts/run_v3.sh predict m3_r34_1536_v3 m1_cnxl_2048_v3 m2_vitl_1536_v3` | GPU, ~2-3 h | `work/preds/<member>/` (P float16, S/D uint8) |
| 9 | `scripts/run_v3.sh rescorer`, then again with `WEIGHTS="..."` | CPU, ~30 min | Phase-2 submission `submissions/submission_v3_rescorer.csv` (v1 post-processing + v2 selector on the new blend) |
| 10 | `NAMES="m3_r34_1536_v3 m1_cnxl_2048_v3 m2_vitl_1536_v3" WEIGHTS="1 1 1" scripts/run_v3.sh stagec` | CPU, ~2 h | full v3 submission on the new members |
| 11 | `scripts/run_v3.sh pseudo` | GPU, ~10-15 h | `work/unlabeled/pl/m1_cnxl_2048_v3+m2_vitl_1536_v3/fold*.npy` |
| 12 | `scripts/run_v3.sh students`, then `predict m1s_cnxl_2048_v3 m2s_vitl_1536_v3` | GPU, ~30 h | gate: student OOF > teacher OOF (`compare_v3.py`) |
| 13 | step 10 with the students in `NAMES` | CPU | final candidate |

Single runs, for debugging or overrides:

```bash
.venv/bin/python src/train_v3.py --config configs/m1_cnxl_2048_v3.yaml --fold 0 --bench-steps 50
.venv/bin/python src/train_v3.py --config configs/m3_r34_1536_v3.yaml --fold 0 --region dml --w-sr 0.5
.venv/bin/python src/compare_v3.py <baseline_oof.csv> <candidate_oof.csv>
```

## Disk

The run needs about 25 GB of extra caches. Each v3 member writes about 12 GB of OOF + test maps at 2048 px.
GONG frames take about 20 GB, and pseudo-labels at 2048 px about 40 GB per fold. The root disk has about
565 GB free. The 5 TB volume (`/dev/vdc1`) is not mounted. To use it:

```bash
sudo mkdir -p /scratch && sudo mount /dev/vdc1 /scratch
export FILSEG_UNLABELED=/scratch/unlabeled    # downloader, QC, pseudo-labels and student configs follow it
```
